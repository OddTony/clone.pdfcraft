# Valid PdfCraft outcomes

Use scenario family for promised success at selected test layer. Selects no runner; pure helpers need no end-to-end journey. Do not activate for unrelated explanation or solely prescribed rejection.

Read [task contract](references/contract.md), [transaction boundaries](references/transactions.md) and relevant [PDF expectations](references/pdf-fidelity.md). Receive operation, supported domain, independent expected facts, authorized effects, current source/configuration/fixture identity and finite cases/time. Reread touched crate README, callers, current tests and automation definition. Current acceptance alone cannot define supported domain.

Write pre-state → action → complete expected result → permitted effects → forbidden effects. Partition materially different behavior: supported permission state, page identity/order, representation, save mode or field appearance. Check content/graph relationships, promised multiplicity/order; page count, parse success or returned `Ok` alone insufficient. Observe saved bytes separately from display-only appearance bytes. Reuse sufficient existing regression; avoid duplicates.

Bounded example: three synthetic pages labeled A/B/C plus unknown dictionary sentinel. Move C to front, rotate page, undo, redo, save and reopen. Independently predeclare expected identities/rotations and sentinel relationships. Compare reopened semantics; unchanged original prefix required only for chosen incremental-eligible save. New-path Save As defaults to full rewrite with different byte expectations. Explicit short trace suffices before considering generated traces.

Alongside hostile/rejection tests, require useful accepted output and authorized publication so reject-everything fails. Include clean second save or next valid edit to expose stale state. Distinguish normal completion from outstanding render work; inspect actual generation consumed. Mocked writer proves local delegation, not filesystem publication.

Run only finite selected checks with installed approved tools; record actual execution identities. Missing Rust, required external oracle or native/browser capability leaves dimension unrun; continue source review or deterministic case design. Stop dependent execution for unresolved validity contract, fixture rights or effect ownership. Preserve failures; do not autoapprove changed fixture.

Report source/fixture identity, selected/executed cases, complete observed semantics/effects, save phase, substitutions, first failures and cleanup. Immediate pass legitimate; no evidence of newly improved test or skill.
