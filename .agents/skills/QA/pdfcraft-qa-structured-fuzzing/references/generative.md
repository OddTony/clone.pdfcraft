## Properties and small models

Before choosing generator, state quantified invariant, domain, preconditions, observable expectation, plausible violating implementation. Workspace already uses [proptest filter tests](https://github.com/storytold/pdfcraft/blob/f0c9901c398372782a4eb001c95638289a5edab0/crates/filters/tests/proptests.rs); inspect member dev-dependencies/lock/features before reuse. Engine: no current proptest dev-dependency. When existing dependencies suffice, use deterministic tables/explicit sequence vectors; do not add package to activate recipe.

Round trips may share writer/reader defects. Add hand-computed vectors/independent expected graph facts and, where approved/available, external oracle process. Generate connected fields together. Bias meaningful partitions; avoid filtering almost everything. Keep named zero/negative/extreme/cyclic/overflow cases alongside generation. Track generated/rejected/eligible/executed cases/commands; model skipping every command must fail adequacy check.

Useful engine model: short vector of page identities/rotations, title, saved checkpoint, undo/redo transitions, dirty state. Define transitions from operation contract, never `scope_of`, production helpers or SUT output. Include invalid commands as expected rejection/no-state-change transitions where appropriate. Sequential models cannot prove parallel schedules; need explicit native barriers or separately qualified instrumented mechanism. Loom/Shuttle/Kani/Miri: no ready-made project harness, optional proposals with limited modeled perimeters.

Every generated case/shrink/replay: fresh model, session, owned files/resources. Await all work; preserve assertion and cleanup errors. Failed reset: stop shrinking unless demonstrably fresh isolated instance created. Bound case count, sequence length, bytes/depth, shrinking, workers, total elapsed/retained resources. Example proptest smoke: process-local `PROPTEST_CASES=32`, `PROPTEST_RNG_SEED=1`, `PROPTEST_MAX_SHRINK_ITERS=256`, outer deadline; verify effective supported configuration first. Exploration bounds, no project gates.

Retain original/minimized exact input/command sequence, seed, effective runner options/version, fixture/source identities, schedule, outcome. Seed alone: incomplete reproducer. Replay concrete minimum alone from clean state; retain failure mechanism while reducing. Distinguish invalid property, generator/fixture leak, product contradiction, unresolved cause. Existing behavior passing immediately: legitimate counterevidence; never manufacture RED.

## Structured inputs and fuzzer accounting

Start accepted small synthetic scaffold/independent expectation. Mutate one named grammar/state rule at a time, then intentional combinations. Preserve raw duplicate members, malformed bytes, PDF structural distinctions through real entry point; generic shrinker repairing anomaly changes experiment. No-crash survival: useful, weaker than reachable semantic/rejection oracle.

Existing [xtask fuzzer](https://github.com/storytold/pdfcraft/blob/f0c9901c398372782a4eb001c95638289a5edab0/xtask/src/fuzz.rs) mutates input bytes, runs child `check-one --edit`; neither source mutation nor coverage-guided fuzzing. Reports hangs, currently fails on crashes; nominal time excludes possible iteration/confirmation/minimization overrun. Linux/FreeBSD child address-space caps cannot prove Windows/macOS caps. Source-observed spawn/wait success classification concerns need controlled runtime verification; attempted spawn cannot count as completed execution. Separate success, ordinary reject, crash, hang, launch/wait error, cleanup. New hangs stay visible even with zero command exit. Detached filters cargo-fuzz harness: distinct nightly/sanitizer/platform prerequisites; no installation/long campaign follows.

## Goldens and source mutants

Golden needs rights, frozen input/producer/config, explicit semantic invariants, reviewed normalization. Keep raw output/diff. Normalize justified incidental variation only; dates, IDs, unknown keys, ordering, encoding or pixel differences may be contractual. Two wrong outputs may match. Preserve deliberately altered semantic sentinel and benign permitted variation as comparator controls. Fixture update: separate reviewed decision, then fresh comparison. Optional oracle absence: declared skip/failure under current `PDFCRAFT_ORACLES_REQUIRED` semantics, never independent agreement.

Source mutation probes sensitivity to selected faults. First pass original selected baseline; list finite relevant candidate set. Optional cargo-mutants needs separately available/approved tooling/current help; manual reversible bad edit in isolated copy may suffice. Tie each mutant to source/operator and requirement-grounded killing assertion. Unrelated build/test failure, timeout, unviable mutant or missing selection: no behavioral kill. Investigate survivors; equivalence needs bounded argument/review. Separate fresh/reused results, preserve first failures, leave broader campaign pending. No score threshold, full workspace run or automatic campaign introduced.

## Tool-specific replay and model boundaries

Proptest persisted failure seeds depend on current strategy; strategy shape or library behavior changes may change concrete input. Preserve named deterministic regression plus seed/persistence data. Persisted replay/rejected cases mean `cases` alone is not aggregate-work cap. Budget replay, local/global rejects, case generation, shrinking, reset/cleanup separately. See [failure persistence](https://proptest-rs.github.io/proptest/proptest/failure-persistence.html) and [locked-version configuration](https://docs.rs/proptest/1.11.0/proptest/test_runner/struct.Config.html). Rejected-all campaign provides no evidence for quantified invariant.

cargo-fuzz: `tmin` reduces single failure input; `cmin` reduces corpus for coverage. Keep original failure/corpus backup before reduction; verify actual child outcome/resulting artifacts plus wrapper exit. Smaller corpus proves neither failure-input minimization nor preserved semantic coverage. Bind target build, instrumentation, corpus hashes, options, exact failing bytes. Sources: [minimization implementation](https://github.com/rust-fuzz/cargo-fuzz/blob/bf2fc668dafda5295aa6fd01825ee67b885f0f2b/src/project.rs), [tmin options](https://github.com/rust-fuzz/cargo-fuzz/blob/bf2fc668dafda5295aa6fd01825ee67b885f0f2b/src/options/tmin.rs), [cmin options](https://github.com/rust-fuzz/cargo-fuzz/blob/bf2fc668dafda5295aa6fd01825ee67b885f0f2b/src/options/cmin.rs).

Windows support needs version-specific verification. cargo-fuzz README still says Unix-like only; [current Rust Fuzz Book](https://rust-fuzz.github.io/book/cargo-fuzz/setup.html) documents Windows MSVC AddressSanitizer setup. Conflict; neither proves usable host harness. Check selected release, installed nightly/native toolchain, bounded approved smoke before support claim. Without them: retain exact replay/deterministic regression proposals; fuzz execution blocked. No installation/overnight campaign to resolve uncertainty.

Loom/Shuttle explore instrumented model only. Inventory every synchronization, thread/task, atomic, timer, I/O boundary; ordinary `std::sync` outside instrumentation gains no schedule exploration from crate import. Loom model bounds and Shuttle chosen schedules/seed limit result. Keep known bad interleaving control, explicit bounds, real cancellation/stale-result/worker-release test for unmodeled consumer. Sources: [Loom](https://github.com/tokio-rs/loom), [Shuttle](https://github.com/awslabs/shuttle). No new dependency/production primitive replacement implied.

Kani: separate bounded-verification proposal. Specify proof harness, assumptions, nondeterministic domain, supported operations, loop/unwind bounds. Establish adequate unwinding assertions/reachability before interpreting success; constrained-away input cannot prove hostile-input safety. No harness/Kani result exists for pack. See [Kani loop handling](https://model-checking.github.io/kani/tutorial-loop-unwinding.html).

Optional insta snapshots: CI comparison mode; explicitly review pending changes before acceptance. Checked documentation: process-local `INSTA_UPDATE=no` disables snapshot-file updates; ensure `INSTA_FORCE_PASS` not enabled, since it may suppress assertion failures. Update modes: effectful; automatically accepted new expectation cannot count as comparison. Keep raw output, semantic sentinel that must fail, permitted incidental variation that must pass. Review redactions/filters as code: stable page identities/order, unknown-object relations, error semantics, confidential remnants must not disappear to stabilize snapshot. See [update controls](https://insta.rs/docs/advanced/), [snapshot review](https://insta.rs/docs/cli/) and [settings](https://insta.rs/docs/settings/). Existing semantic assertions/checked-in literal outputs suffice without insta.
