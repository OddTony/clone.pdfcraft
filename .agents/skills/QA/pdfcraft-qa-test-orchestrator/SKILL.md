# Coordinate verification

Use when integration owner needed. Single engine regression, source question or UI check may use relevant skill directly. Skill authorizes no implementation, installation or publication.

Read current repository instructions and [scope contract](references/contract.md). Inputs: requested claim, relevant revision/dirty changes, acceptance criteria, existing results, available hosts, allowed effects. When local `plan/` or internal background documents unavailable, use public architecture, crate READMEs, parity entries/source; never invent contents.

1. State deliverable; distinguish planning/source inspection/executed behavior/product qualification. Select only necessary evidence layers/scenario techniques. Preserve required repository gates; catalog not phase checklist.
2. Dependency graph: one owner for shared configuration, integration, final records. Example: review engine edit assertions separately from automation page-number conversion; save/reopen integration depends on agreed synthetic fixture/expected semantics.
3. Check build effects; allocate finite aggregate budget before launch. Follow [tool prerequisites](references/tooling.md) for unavailable capabilities. Separate worktrees/`CARGO_TARGET_DIR` values alone cannot isolate writable caches, output files, ports or CPU.
4. Dispatch only with request/applicable policy delegation authority. Supply narrow objective, authoritative inputs, disjoint writes, controls, budget, dependencies, required outputs. Otherwise same graph sequentially.
5. Inspect files/native evidence at each input barrier. Progress message, source-defined test or agreeing reviewer adds no runtime execution. Classify first failures; retain valid tests-only regressions without silent production repairs.
6. Integrate stable combined state; invalidate only evidence affected by later changes. Reconcile planned checks/actual outcomes via [evidence requirements](references/evidence.md); keep doctests/platform evidence explicit.

Stop affected phase for unknown authority, resource ownership conflict or unavailable required environment. Continue separable work; name next owner. Close with scope completed, raw artifact identities, failures, unexecuted gates, consumed budgets, resource disposition, next action. Persist checkpoint for coordinated/interrupted work; concise prose suffices for bounded task.
